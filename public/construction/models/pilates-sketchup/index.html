Produce the reusable model files

  1. Keep the original SKP. Open it in SketchUp Desktop and download paila_export.rb.
  2. Open SketchUp's Ruby Console and run load UI.openpanel('Choose paila_export.rb', '', '*.rb'). Choose a new export location. The script reads the model and writes files; it does not edit or purge the source.
  3. The output contains scene.json, entities.jsonl, materials.json, definitions.json, components.csv, textures, README.txt and checksums. The exporter is prepared from the documented SketchUp Ruby API; execution against this file is still unverified.
  4. Load scene.json above to inspect linked views. For a queryable archive, run python ingest-scene.py scene.json NEW_OUTPUT_FOLDER to create SQLite, SQL, instance JSONL and a duplicate-candidate report.
  5. Alternatively provide a compressed SKP below 256 MiB, or export GLB / DAE plus an Outliner report. Then the actual model can be ingested and its plans published.

One SKP normally contains one model document with many groups and reusable component definitions. Many components do not, by themselves, mean duplicated buildings. Preserve options and instances until their placement and hierarchy are reviewed.

JSON and SQLite are useful derivatives. The unchanged SKP is the binary original and remains necessary for full SketchUp fidelity. The viewer shows basic face colours; UVs, back faces and textures are preserved in export data but texture mapping, scene-specific tag states and images are not rendered here.
